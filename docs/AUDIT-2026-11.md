# Reliability audit — November 2026 (5.4.0)

A structured bug hunt across the whole app, not just the tested core. This page records what
was checked, how, what was found, and what was **not** checked, so the next audit can start
where this one stopped.

## Summary

| # | Finding | Severity | Status |
| --- | --- | --- | --- |
| 1 | With the app open in two tabs, a save in one tab silently erased attempts saved in the other. | **High** — data loss | Fixed, regression test |
| 2 | Links to the five V5 panels (`/#retests`, `#papers`, `#intelligence`, `#weekly`, `#study-tracker`) opened Command instead. | Medium | Fixed, regression test |
| 3 | A fresh transfer or delayed retest that closed no check was still reported as “Evidence saved”, so a student logging a retest before its due date (or matching two checks) believed the check had closed. | Medium — misleading | Fixed: the save message now says why no check closed |
| 4 | A new release could precache stale files from the browser's HTTP cache, so the offline copy could mix old and new scripts. | Low | Fixed, contract test |

No crash or broken text (NaN, `undefined`, `Infinity`, `[object Object]`) was found by the
UI fuzzer described below.

## Methods

| Method | What it covers | Result |
| --- | --- | --- |
| Existing suite (`npm run check`) | Lint, strict type check, 120+ unit and property tests, browser, accessibility, keyboard, offline, snapshot and performance tests | All pass |
| Pattern review | Every `JSON.parse`, `localStorage` write, `innerHTML` assignment, date conversion and `Math.max(...)` in `app.js`, `v5-additions.js`, the Study Tracker and Physics Intelligence | No defect; each site is guarded or reads trusted data |
| **UI fuzzing** (new, `npm run fuzz:ui`) | Random student histories replayed through the real retest rules, loaded into Chromium, every panel visited | See [results](#ui-fuzzing-results) |
| Scenario reproduction | Multi-tab use, deep links, editing an attempt deleted elsewhere, retests logged early or ambiguously | Findings 1–3; the edit case was already handled |
| Service-worker review | Install, activate, update and offline paths | Finding 4 |

### UI fuzzing results

`tests/fuzz/ui-fuzz.mjs` generates histories with up to 40 attempts of every type, error family
and confidence level, dates from 400 days ago to 30 days ahead, zero-mark totals, guesses and
daily entries. It replays them through `createRetests` / `applyRetestOutcome` so open, failed,
passed and overdue checks all appear, then opens all 14 panels and fails on any page error,
console error or broken text.

## Diagnosis notes

**Finding 1 (multi-tab data loss).** Each tab keeps the record in memory and writes the whole
record on save. Tab B, opened before tab A's save, still held the old record; its next save
replaced A's work. Reproduced with two pages in one browser context (`tests/e2e/multi-tab.spec.mjs`,
failed before the fix). Fix: the app now listens for the browser's `storage` event, reloads the
record through the normal validation path, re-renders and tells the student. The Study Tracker
already did this; the main app did not.

**Finding 2 (deep links).** `app.js` resolved `#panel` links at start-up, before
`v5-additions.js` had created the V5 panels, and its allow-list omitted them. Fix: the V5 layer
resolves the hash again after building its panels, and on later hash changes.

**Finding 3 (silent non-closure).** By design a verification attempt closes a check only when it
is on or after the due date and matches exactly one open check (or names it). That rule is
correct and unit-tested, but nothing told the student when it didn't apply. Fix: a new pure
function, `PowerhouseCore.explainUnclosedVerification`, classifies the outcome as `too-early`
(with the due date), `ambiguous` (with the count) or `no-open-check`, and the save message uses
it.

**Finding 4 (stale precache).** `cache.addAll` goes through the HTTP cache. GitHub Pages serves
files with a short max-age, so a service worker installed right after a release could store the
previous release's files under the new cache name. Fix: precache with `cache: 'reload'`.

## Not covered (known gaps)

- Real devices and browsers other than Chromium (Safari's storage eviction in particular).
- Two tabs saving within the same few milliseconds; the fix narrows that window to near zero but
  `localStorage` has no transactions.
- Very old Android WebViews without `Intl.DateTimeFormat` time-zone support (the Study Tracker
  falls back to UTC dates there).
- The open product decision on retest stage order (stage 2 can close before stage 1); see
  `ROADMAP.md`.

## Reproducing this audit

```bash
npm ci
npm run check                               # full existing suite
npm run fuzz:ui                             # 60 histories, fixed seed
FUZZ_RUNS=300 FUZZ_SEED=7 npm run fuzz:ui   # a longer, different run
```

On machines without Playwright's browser: `PW_CHROMIUM_PATH=/path/to/chrome npm run fuzz:ui`.
